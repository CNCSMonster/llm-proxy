# ADR-017: 安全默认值 + 用户覆盖 > 强制限制

**状态**：已接受  
**日期**：2026-07-06

## 背景

代码审查发现 `config.toml` 以 `0644` 权限写入，多用户服务器上其他用户可读取文件中的 `api_key` 字段。

但项目的设计已经规避了明文密钥风险：
- `connect` 命令 → 写入 `${VAR_NAME}` 引用
- `init` 命令 → 写入 `${ENV_VAR}` 引用
- 文档推荐的方式也是环境变量引用

所以 `config.toml` 在正常使用流程下**不包含明文 API Key**。0644 权限只在用户**主动选择**写明文 key 时才有风险。

## 决策

**不改文件权限，不强制用户的安全选择。**

项目提供安全默认值（`${ENV_VAR}` 引用），但当用户刻意绕过安全路径（写明文 key）时，项目不替他改文件权限。

理由：
1. 正常流程（`connect`/`init`）已经规避风险
2. 用户写明文是**主动选择**，应该自己承担后果
3. 强制 `chmod 600` 会让用户困惑："我明明写了 key，为什么读不到？"（权限问题难排查）

## 替代方案（已拒绝）

### 强制 0600 权限
- 优点：即使写明文也安全
- 缺点：用户可能不理解为什么权限被改了，排查困难

### 明文 key 自动转为 `${ENV_VAR}` 引用
- 优点：完全消除风险
- 缺点：过度干预用户配置，破坏用户意图

### `Validate()` 中对明文 key 打印警告
- 优点：提醒用户
- 缺点：用户可能忽略警告，且增加噪音

## 影响

- `config.Save()` 保持 `0644` 权限
- `status` 命令对明文 key 显示脱敏预览 + 警告（已在 status.go 实现）
- 未来遇到类似决策（其他敏感配置）参考此原则：**提供安全默认值，但不强制用户的安全选择**
