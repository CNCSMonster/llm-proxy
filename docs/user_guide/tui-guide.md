# TUI 使用指南

llm-proxy 的主 TUI 提供三个交互入口：

| 命令 | 功能 |
|------|------|
| `llm-proxy provider`（无子命令） | 主面板：Provider 管理（列出、增删改、模型重选、登录、fallback、usage） |
| `llm-proxy model`（无子命令） | 主面板：Model 管理（列出、增删改、复制、重命名、协议绑定编辑） |
| `llm-proxy connect`（无参数） | 添加 provider 的完整交互流程 |

`provider` 与 `connect` 共用同一套界面组件；`model` 是独立的 Model 管理入口，不会进入 connect 向导。除此之外，llm-proxy 还提供两个独立的辅助 TUI：

| 命令 | 功能 |
|------|------|
| `llm-proxy usage` | 浏览 Token 用量统计 |
| `llm-proxy doc` | 浏览内置用户文档 |

本文先按主 TUI 界面列出快捷键，再说明辅助 TUI 与全局控制键。

---

## 1. Provider 管理面板

Provider 管理页底部帮助栏固定从左侧开始显示：正常高度分为两行，第一行优先显示搜索、添加、复制、模型重选、编辑、详情和退出，第二行显示删除、fallback、登录、usage、重置 usage 和刷新。较矮终端会保留第一行核心入口，避免 `[m] Models` 被右对齐裁剪。

列表各行末尾实时展示该 Provider 的整体冷却状态：若存在针对该 Provider 的有效冷却，标红显示 `[COOLDOWN until <到期时间>]`；无冷却时标绿显示 `[OK]`。按 `r` 可随时重新拉取并刷新状态。

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j` | 上下移动光标 |
| `/` | 进入过滤模式（输入关键字过滤） |
| `Enter` | 查看选中 provider 的详情 |
| `a` | 添加 provider（进入 connect 流程） |
| `c` | 复制选中 provider（进入 CopyConfigure，默认名称 `SOURCE-2`） |
| `m` | 重选选中 catalog provider 的模型；当前 bindings 会预选，确认后按选择集重整该 provider 的 catalog bindings |
| `d` | 删除选中 provider（确认对话框） |
| `e` | 编辑选中 provider（自定义配置编辑器） |
| `f` | 为选中 provider 配置 fallback |
| `l` | OAuth 登录（非 OAuth provider 会显示提示） |
| `r` | 刷新 provider 列表（自动刷新过期的 OAuth token） |
| `R`（Shift+R） | 重置选中 provider 的 usage 配额（确认对话框） |
| `u` | 查看选中 provider 的 usage 统计摘要 |
| `q` | 退出 |

## 2. Model 管理面板

`llm-proxy model` 打开独立 Model 列表。帮助栏正常高度分两行：第一行是搜索、新增、复制、重命名、详情和退出，第二行是删除。`model --select <MODEL>` 直接进入详情。

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j` | 上下移动光标 |
| `/` | 进入过滤模式 |
| `Enter` / `l` | 查看选中模型详情 |
| `a` / `+` | 新增空白模型（草稿，按 `s` 才写入） |
| `c` | 复制选中模型（预填 `SOURCE-N`，完整复制参数和三协议绑定；按 `s` 才写入） |
| `r` | 重命名选中模型 |
| `d` / `-` | 删除选中模型（二次确认） |
| `q` | 退出 |

### 2.1 Model 详情

列表按 `Enter`，或 `llm-proxy model --select <MODEL>`，进入详情。已保存模型的标量字段改完立即写入；新增 / 复制草稿要按 `s` 才创建。各协议绑定行下方列出的具体 Provider 绑定条目末尾，均展示该绑定的冷却状态（`[COOLDOWN until <到期时间>]` 标红或 `[OK]` 标绿）。

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j` | 在字段间移动 |
| `Enter` | 编辑当前标量字段；thinking 直接开关；协议绑定行进入绑定编辑器 |
| `s` | 保存新增 / 复制草稿 |
| `r` | 重命名当前已保存模型 |
| `Esc` | 取消编辑或返回列表（草稿不写入） |

已保存模型的 `model_id` 按 `Enter` 走重命名流程，不会在详情页就地改 ID。

### 2.2 协议绑定编辑器

在详情页选中 `openai_chat_providers` / `openai_responses_providers` / `anthropic_providers` 后按 `Enter`。只编辑当前模型在该协议下的 Provider 链，顺序即 fallback 优先级。`[s]` 原子替换该协议列表。新增 / 复制草稿必须先保存模型，才能进入此编辑器。

| 按键 | 功能 |
|------|------|
| `a` | 从具备该协议端点、尚未绑定的已配置 Provider 中添加 |
| `e` | 编辑当前绑定的 upstream model |
| `K` / `J` | 上移 / 下移当前绑定 |
| `d` / `-` | 移除当前绑定（先确认） |
| `s` | 保存并返回详情 |
| `Esc` | 放弃未保存改动并返回详情 |

### 2.3 模型删除确认

列表按 `d` 进入。删除只移除前端模型条目，不会删除任何 Provider 或凭据。

| 按键 | 功能 |
|------|------|
| `y` | 确认删除 |
| `n` / `Esc` | 取消并返回列表 |

### 2.4 路由模型（只读）

声明 `reasoning_routes` 的路由模型是纯转发层：它没有自己的执行参数，客户端看到的上下文窗口、max output、输入模态、思考等级词表都是**派生值**（来自路由目标；目标间的客户端可见能力强制一致，见 spec §4.2 rule 9）。列表与详情显示这些派生值并标注 `(derived)`，详情页标题为 `[Routing Model - Read Only]`，`Routes` 行按 `level → target` 逐条列出路由表。

- 能力字段只读：`context_window` / `max_output_tokens` / `thinking` / `features` / `Routes` 行上按 `Enter` 不进入编辑，`s` 保存与协议绑定编辑器均被拒绝（提示"路由模型为只读展示，不可在此保存修改"）。
- `model_id` / `r` 的重命名（见 §5）仍可用，不触碰能力派生；若被改名的是路由目标，各路由表的 `target` 引用会同步更新。
- 复制（`c`）被拦截并提示"路由模型暂不支持在 TUI 中复制，请在配置文件中配置"。
- 路由表本身也只读；增删路由或调整目标请直接编辑 `config.toml` 的 `reasoning_routes`。

## 3. Provider 详情面板

在管理面板按 `Enter` 进入，展示 provider 的认证状态、各协议端点与绑定的模型列表。

| 按键 | 功能 |
|------|------|
| `Esc` | 返回管理面板（保持光标位置） |
| `c` | 复制当前 provider（进入 CopyConfigure） |
| `m` | 重选当前 catalog provider 的模型；当前 bindings 会预选，确认空选择会取消该 provider 的全部 catalog bindings |
| `↑` / `k`、`↓` / `j` | 在绑定的模型列表中移动光标 |
| `r` | 重命名光标处模型（见下文"模型重命名"） |
| `d` | 删除当前 provider（确认对话框） |
| `e` | 编辑当前 provider |

## 4. connect 流程

无参数 `llm-proxy connect` 启动添加 provider 的交互流程，按顺序经过以下界面：

```
产品选择 → 命名屏（仅第 2+ 次 connect）→ env 选择 → 模型选择 / fallback 配置 → 探测确认 → 完成
```

- **首次 connect**：默认进入**模型选择**界面（勾选模型模板）。
- **再次 connect 同一产品**：默认进入 **fallback 配置**界面（把新 provider 配置为已有 provider 的 fallback），且先经过**命名屏**（预填 `产品名-2` 等递进 ID）。
- **探测确认**排在**本地 env var 存在性检查之后、网络探测之前**；env var 缺失时不会进入该屏，而是停留在模型选择页并点名缺失的变量。

### 4.1 产品选择

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j`、`Ctrl+P`、`Ctrl+N` | 移动光标 |
| `/` | 过滤 |
| `Enter` | 确认选择 |

> **OpenRouter**：产品与模型模板不内置在二进制中。选中该产品时按公开免鉴权接口
> **联网拉取 450+ 模型**（首次进入即拉取，结果缓存到本地、24h 有效）。
> 断网自动降级到历史缓存；无缓存时提供 `Esc` 退出与 `r` 重试；缓存超过 24h 未刷新时界面显示**降级**警告。

### 4.2 命名屏（仅第 2+ 次 connect）

为新的 provider 指定名称。有两种模式：

- **浏览模式**（默认）：`e` 进入编辑模式，`Enter` 直接确认预填名称。
- **编辑模式**：直接输入字符（字母、数字、`-`、`_`）、`Backspace` 删除、`←`/`→` 移动光标、`Enter` 确认。输入时**实时校验重名**，与已有 provider 重名时显示错误并禁止确认。

### 4.3 env 选择

选择 API Key 环境变量。带 `you may want` 标记的条目是根据产品/provider 命名的推荐项（如 `DEEPSEEK_API_KEY`）。

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j`、`Ctrl+P`、`Ctrl+N` | 移动光标 |
| `/` | 过滤 |
| `Enter` | 确认选择 |
| `s` | 跳过（不设置 API Key，适用于 Ollama 等无需认证的产品） |

### 4.4 模型选择

从 catalog 中勾选模型模板（作为 Model ID 绑定到新 provider）。

| 按键 | 功能 |
|------|------|
| `Enter` | 确认选择，进入写入流程 |
| `Space` | 切换光标处模型的勾选状态 |
| `a` | 全选 / 取消全选 |
| `↑` / `k`、`↓` / `j`、`Ctrl+P`、`Ctrl+N` | 移动光标 |
| `/` | 过滤 |
| `F` / `f` | 进入 fallback 配置界面 |
| `c` | 复制光标处模型（见下文"模型复制"） |
| `r` | **（仅在线目录产品）**强制刷新模型目录；防抖窗口内连按只发 1 次请求 |

- 每行模型下方有一行暗色详情：`ctx=? max_out=? image=✗ [thinking]`。`?` 表示**目录未声明**该值（不虚构默认）；`[thinking]` 表示该模型**声明了思考等级**，接入后客户端会出现对应思考控制项；`image=✓` 表示支持图片输入。
- 在线目录产品（如 OpenRouter）的 `/` 过滤是 **Fuzzy 模糊搜索**，450+ 模型毫秒级过滤；刷新失败或缓存过期时列表顶部显示降级警告。

> 零选择时按 `Enter` = 跳过：只创建 provider，不绑定任何模型。

### 4.5 探测确认

模型选择按 `Enter` 后、**网络探测开始前**出现的确认屏。

| 按键 | 功能 |
|------|------|
| `↑` / `k`、`↓` / `j` | 在「探测（推荐）」与「跳过探测」之间切换 |
| `Enter` | 按当前高亮项确认 |
| `N` / `n` | 直接跳过探测 |

- **默认高亮「探测（推荐）」**；确认后显示成本预估（`N 个模型（约 N~2N 次请求）`）。
- 覆盖**全部产品**，不只 OpenRouter。
- **零选择模型时本屏不出现**，直接进入写入流程。
- 「跳过探测」只跳过**网络可达性探测**，**不豁免本地凭据校验**——两者是相互独立的检查。

**探测发现模型不可达时**：仍会把全部选中模型探完（单个失败不中断整批），随后汇总成一条清单交还用户：

- **TUI**：弹出警告框逐条列出不可达模型与原因，选「**继续**」即以跳过探测的方式重试写入（配置照常写入，这些模型稍后仍可重试），选「**返回**」回到产品/模型选择。
- **非 TUI 的 CLI**：见 [CLI 使用指南](cli-guide.md)「Connect 命令 → 探测失败的处置」。

### 4.6 fallback 配置

双栏界面：左侧选择 target provider，右侧勾选 `模型:endpoint` 组合，把新 provider 批量插入为这些组合的 fallback（同产品约束，upstream 自动复制 target 的值）。

| 按键 | 功能 |
|------|------|
| `Tab` | 切换焦点（target provider 列表 ↔ 选项列表） |
| `Space` | 勾选/取消勾选选项（选项栏焦点时） |
| `Enter` | 确认并写入 |
| `M` / `m` | 切回模型选择界面 |
| `↑` / `k`、`↓` / `j` | 在焦点栏内移动光标 |

> connect 流程中零选时按 `Enter` 会显示提示"未选择任何 (model, endpoint) 组合"；此时按 `Esc` 跳过 fallback 配置、直接完成添加。从 Provider 管理面板进入且无可用选项时按 `Enter` 直接返回列表。

## 5. 模型重命名 / 复制

模型重命名、完整复制也可从独立 Model 管理 TUI 进入；CLI 另有 `model rename` / `model add --copy-from`。connect 流程里的复制仍走确认屏。

### 模型重命名

1. 在 Model 管理面板选中模型按 `r`，或在 Model 详情按 `r` / 选中 `model_id` 后按 `Enter`。
2. 也可在 Provider 详情用 `↑`/`↓` 选中绑定模型后按 `r`。
3. 输入新 Model ID，按 `Enter` 校验重名并进入确认。
4. 确认对话框按 `y` 提交——重命名会**自动更新所有 binding 中对该模型的引用**。从 Model TUI 进入时成功后返回模型列表。

> 与命名屏/复制屏不同（实时校验），重命名在按 `Enter` 时才校验重名。

### 模型复制（Model 管理）

1. 在 Model 管理面板选中源模型，按 `c`。
2. 进入与新增相同的编辑表单，预填 `SOURCE-N`，并带上源模型的参数与三协议绑定。
3. 按 `s` 写入；源模型保持不变。未按 `s` 前不写配置。

> 路由模型（见 2.4）不支持复制，按 `c` 只会显示提示。

### 模型复制（connect 模型选择）

1. 在 connect 流程的模型选择界面，用 `↑`/`↓` 选中源模型，按 `c`。
2. 进入复制确认屏（**初始即编辑模式**）：直接输入新 Model ID（默认 `源ID-<序号>`，实时校验重名）。
3. 按 `Enter` 提交——完整复制模型参数及 provider 绑定；源模型保持不变。

> 与命名屏不同（默认浏览模式，需 `e` 进入编辑），connect 复制屏默认就是编辑模式，输入后一次 `Enter` 即提交。

### Provider 复制

1. 在 Provider 管理面板（或详情页）选中源 provider，按 `c`。
2. CopyConfigure 先预填递进名称（如 `deepseek-2`），实时校验重名；`e` 编辑，`Enter` 进入认证确认。
3. API Key provider 必须显式确认 `api_key_env`（可编辑现有名称，或按 `s` 复制为无密钥）；工具不会根据 Provider ID 编造环境变量名。
4. OAuth provider 只复制配置，新实例 `auth.account` 等于新 ID，提交后进入现有登录界面。
5. 复制成功后返回列表，光标停在新 provider 上。模型绑定不会被复制。

## 7. 全局控制键与通用按键

主 TUI（`provider`、`model`、`connect`）和辅助 TUI（`usage`、`doc`）共享以下终端级控制键语义；全局控制键先于页面业务快捷键处理：

| 按键 | 功能 |
|------|------|
| `Ctrl+C` | 请求退出当前 TUI，并通过终端会话清理路径恢复终端状态 |
| `Ctrl+D` | 执行 EOF 语义：非编辑界面直接退出；主 TUI 的空输入流程退出或返回父页面；主 TUI 正在编辑且输入非空时保留现有内容，不提交、不清空、不退出 |
| `Ctrl+Z` | 在支持作业控制的平台上，先恢复终端再挂起进程；恢复至前台后重新进入 TUI 并重绘 |

页面级通用按键：

| 按键 | 功能 |
|------|------|
| `Esc` | 返回上一级 / 取消 |
| `y` / `n` | 确认对话框确认 / 取消 |
| `Ctrl+N` / `Ctrl+P` | 下拉列表向下 / 向上（Emacs 风格导航） |

> `usage` 与 `doc` 没有文本编辑状态，因此其中的 `Ctrl+D` 与 `Ctrl+C` 一样请求退出。`Ctrl+Z` 的挂起能力取决于平台是否支持对应的终端作业控制。
